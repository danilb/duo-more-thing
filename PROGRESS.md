# duo — iPhone Duo fold-blur эффект на MacBook

Файл прогресса для передачи между агентами. Обновлять при каждом значимом шаге.

## Задача
Воспроизвести на MacBook анимацию iPhone Duo: при закрытии крышки интерфейс
верхней части экрана прогрессивно размывается и уходит в тень, градиент блюра
сходит на нет к нижнему краю экрана (это ось шарнира). При открытии — обратно.
Эффект привязан к реальному физическому углу крышки.

## Ключевые находки (research, 2026-09-11)

### 1. Датчик угла крышки СУЩЕСТВУЕТ и доступен из user space
Введён с MacBook Pro 16" 2019. Reverse engineering: samhenrigold/LidAngleSensor.
Доступ: IOKit HID, **feature report** (не input report).

- Vendor ID `0x05AC`, Product ID `0x8104`
- PrimaryUsagePage `0x20` (Sensor), PrimaryUsage `0x8A` (Orientation)
- `IOHIDDeviceGetReport(dev, kIOHIDReportTypeFeature, reportID: 1, buf, &len)`
- ответ 3 байта: `[0x01, lo, hi]` → угол = `UInt16(hi) << 8 | UInt16(lo)` в ГРАДУСАХ
- 0° = закрыт, ~130° = типичное рабочее положение

### 2. ПРОВЕРЕНО на этой машине (Mac14,9 = MacBook Pro 14" M2 Pro, macOS 26.6.2)
`scratchpad/probe.swift` перечислил HID-устройства. Результат:
```
vid=0x05AC pid=0x8104 page=0x20 usage=0x8A   <== ТО САМОЕ
   feature report id=1 len=3 bytes=[1, 130, 0] -> angle=130   ✅ РАБОТАЕТ
   feature report id=2 len=2 bytes=[2, 39, 0]
   feature report id=3 len=6 bytes=[3, 130, 169, 136, 1, 0]  (возможно суб-градусная точность: 130 + 169/256?)
```
Вывод: НЕ нужна камера, НЕ нужны костыли. Угол читается напрямую, 60 Гц.
(Три других устройства с pid=0x8104 и page=0xFF00 на feature report отвечают
ошибкой 0xE00002C7 — их надо пропускать, матчиться строго по page=0x20/usage=0x8A.)

### 3. Прототипы, которые уже существуют (референс, не наш код)
- `lqSky7/iphone-duo-macos-animation` (macTilt) — ровно эта задача, Swift + Metal +
  ScreenCaptureKit, ~2850 строк, есть 3D-перспектива сгиба, liquid-glass панель,
  меню-бар. Склонирован в `<scratchpad>/mactilt` для изучения. Оттуда взята
  схема матчинга HID-устройства.
- `samhenrigold/LidAngleSensor` — первоисточник по датчику.
- Параметры оригинального эффекта (из разборов Android-реконструкции):
  максимальный радиус блюра ~72 исходных пикселя, затемнение = 2× силы перехода
  с ограничением до чёрного, блюр и затемнение идут по координатам изображения.

## Архитектурное решение
Системный интерфейс заблюрить «по-настоящему» публичными API нельзя. Поэтому:
оверлей-окно поверх всего (уровень CGShieldingWindowLevel) с замороженным
снимком экрана, отрисованным в Metal с прогрессивным блюром.

- Снимок: ScreenCaptureKit `SCScreenshotManager.captureImage` в момент «взвода»
  (угол ушёл ниже startAngle+20° при закрытии) — до показа оверлея, поэтому
  оверлей не попадает в кадр. Fallback без разрешения Screen Recording — обои.
- Блюр: mip-пирамида (MPSImageGaussianPyramid) + сэмплирование с переменным LOD
  во фрагментном шейдере = настоящий variable blur, дёшево на GPU.
- Модель градиента: d = расстояние от шарнира (низ экрана) 0..1,
  s = сила сложения 0..1, W = ширина градиента,
  `p = (1-s)*(1+W) - W`, `n = smoothstep(saturate((d-p)/W))`,
  `lod = n^gamma * maxLod`, затемнение = smoothstep по n.
  При s=0 блюра нет нигде, при s=1 блюр максимален везде.
- Плюс лёгкое сжатие (squash) картинки к шарниру — имитация ракурса.

## Что проверено и как

- Датчик: `scratchpad/probe.swift`, угол читается, 130°.
- Эффект: `--render-test` на реальном скриншоте рабочего стола, 6 стадий —
  градиент и затемнение выглядят как у iPhone Duo.
- Оверлей вживую: `open build/Duo.app --args --hold 0.55` + `screencapture` —
  окно перекрывает всё, включая меню-бар, эффект виден.
- Собственно движение крышки протестировать из агента нельзя.

## Подобранные дефолты (Settings.swift)
startAngle 90°, endAngle 20°, maxLod 7 (128 px), gradientWidth 0.85,
gamma 1.4, frontCurve 1.5, darkness 0.95, darkStart 0.5, squash 0.07,
followSpeed 26, releaseDelay 2.5 c.

`frontCurve` — важный параметр: >1 держит резкость у шарнира дольше, иначе на
80% сложения весь экран уже чёрный (первая версия так и выглядела).

## Известная засада с разрешением
TCC приписывает запрос Screen Recording «ответственному» процессу. Если
запускать Duo.app из терминала/агента, диалог приходит от имени родителя
(у нас был «Claude»). Запускать надо из Finder/Spotlight. Пока разрешения нет,
работает фолбэк на обои — эффект виден, но вместо интерфейса обои.

## Итерация 2 (по фидбеку)

Что просили и что сделано:

1. **«Пропадает интерфейс, остаётся только background»** — это был фолбэк на
   обои: разрешение Screen Recording не выдано, приложение молча деградировало.
   Теперь состояние источника видно всегда (плашка «живой экран» / «обои»,
   текст с причиной, кнопка выдачи разрешения). Само разрешение выдать может
   только пользователь, и только запустив Duo.app из Finder.
2. **3D-перспектива.** Кадр рисуется не полноэкранным треугольником, а quad'ом,
   повёрнутым вокруг нижнего края (шарнира) и спроецированным перспективой.
   Проекция подобрана так, что при strength = 0 панель совпадает с экраном
   пиксель в пиксель: `f = 2·depth`, тогда при θ=0 углы панели попадают ровно
   в NDC ±1. Дальше панель уходит вглубь, вокруг — чёрная пустота.
3. **Эффект должен сильнее ощущаться в начале.** Старая модель (бегущий фронт
   размытия) не разделяла «как быстро мылится верх» и «как долго держится
   резкость у шарнира» — из-за этого верх начинал мылиться поздно. Заменено на
   две независимые кривые:
   `n = mix(s^hingeCurve, s^topCurve, d^shape)`, где topCurve < 1 даёт резкий
   отклик у верхнего края, hingeCurve > 1 держит резкость у шарнира.
   Старые параметры gradientWidth / gamma / frontCurve / squash удалены.
4. **Liquid Glass панель настроек.** SwiftUI, `glassEffect` + `GlassEffectContainer`,
   подложка — размытый снимок экрана (иначе стеклу нечего преломлять и оно
   выглядит как плоский прямоугольник). Живое превью эффекта со слайдером силы,
   рендерится офскрин тем же шейдером. Старое окно TuningWindow удалено.
   Deployment target поднят до macOS 26.0 ради этих API.

Новые дефолты: startAngle 100°, endAngle 18°, armLead 30°, maxLod 7.2,
topCurve 0.45, hingeCurve 4.5, shape 1.6, darkness 0.97, darkStart 0.45,
tiltAngle 38°, tiltCurve 1.3, depth 2.2, followSpeed 26, releaseDelay 2.5 с.

Проверено: сборка, панель (скриншот docs/panel.png), офскрин-рендер всех стадий,
датчик живьём (125–130°). НЕ проверено по-прежнему: реальное движение крышки,
поведение после сна и на локскрине, работа с выданным разрешением на запись
экрана (его выдаёт только пользователь).
